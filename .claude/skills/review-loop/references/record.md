## Record the review
When the loop ends, first (after any Fable final pass) make the final Argon call if Gemini checks calls for one and handle its findings. Then run the project's tests one last time through the gate and show the result: `python3 <gate> run-check --stamp` (`<gate>` as below; in the background when the suite is slow, and wait for it to exit before `--mark`). It runs the check `--mark` would run and, on a pass that leaves the tree unchanged, stamps the tree so `--mark` does not run it again. Also, if the ticket's acceptance criteria have `Proof:` lines, save them to a scratch file (outside the repo) and run `python3 -B <this skill's folder>/scripts/prove.py run <file>`, then `... prove.py attest <file>`: it runs each command proof (not `manual:` ones), refuses a malformed `Proof:` line, and prints the `AC-Proof:` line for the PR body; show its results for the proof table and compare each printed command with its criterion. A proof that is exactly the check command is not run again when the `run-check --stamp` stamp matches this tree, branch and command: `run` prints `proof N: reused check stamp <tree>` and counts it as passed, and the stamp stays for `--mark` (NFX-218). So run `prove.py run` after the stamp run exits, and before any edit. If the stamp run fails on a fix that had no full run yet (delta or post-Argon), repair or revert it (a reverted delta fix becomes `follow-up`) and stamp again. Record nothing if there was nothing to review or a test still fails: say so, and leave the gate blocking. Otherwise, run `python3 <gate> --mark --findings <open high count + open med at 60 or more> --tier <final tier> --reasons "<reasons for the final tier, including your own reason for a raise>"` (`python` on Windows), where `<gate>` is the gate path printed in the gate's block message, or the path in the `command` of the review-gate hook in your tool's hook config (`~/.claude/settings.json` for Claude Code, `"$(git rev-parse --absolute-git-dir)/nousfx-gate/current/hooks/review-gate.py"` in a cloud session with no `~/.claude`, which the project hook fills from the default branch on any Bash call, run as `python3 -I -B <gate>`; never run the repo copy; the plugin's `hooks.json` for agy). The mark runs the project's check command itself, unless a stamp from `run-check --stamp` matches this tree, branch and command, and refuses to record when it fails, times out, edits files or is missing (rules: `docs/review-gate.md`, "The check command"). Show its output. If it refuses, fix the cause and mark again; do not report the findings count as if the review had been recorded. Without a mark, and with a mark that has open findings, the PR gate hook blocks `gh pr create`. Run it after the final fix and test run, since any later edit invalidates it. If the user chose to skip the review, use `--skip "<their reason>"` instead; only that gets a PR past open findings or failing tests, and it runs no check.
